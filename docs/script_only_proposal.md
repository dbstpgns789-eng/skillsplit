# script-only 판정 범위·방식 (왕민 결정, 세훈 님께 통보)

작성 2026-11-07. 처음에는 세훈 님께 묻는 제안으로 썼고, 같은 날 왕민이 아래 안으로 정해 세훈 님께 통보하는 것으로 바꿨다(반대 의견은 동결 전까지 받음). 에이전트(Claude)와 함께 작성했다. 숫자는 dev 결과 파일(`data/runs_dev/script_evidence.csv`, `results/stage1/stage1_v1_dev.jsonl`)에서 계산했고 원문은 읽지 않았다. "가정"이라고 쓴 곳은 실제 비율을 모르는 상태의 모의 계산이다. test 구성은 보지 않았다.

보고 위치(11-09 공지): 전체 재현율이 기본 보고 값이다. script-only 제외 재현율은 표본 판정으로 낸 보조 추정값으로, 전체 재현율과 구분해 보고하고 대신하지 않는다. 탐지기 입력은 SKILL.md뿐이며 동봉 스크립트를 읽는 탐지는 후속 확장이다.

## 0. 통보

2026-11-07 세훈 님과 준서 님께 §1~§7의 요지를 알렸다. 반대 의견은 동결(11-08 저녁) 전까지 받는다.

## 1. 판정 범위: (가) 코드 파일이 있는 악성 전부

N = 악성 수, H = 걸린 악성, S_hit·S_miss = 걸린 쪽과 놓친 쪽의 script_only 수라고 하자.

| 범위 | 제외 재현율 |
|---|---|
| (가) 필요조건을 채우는 악성 전부 | (H − S_hit) / (N − S_hit − S_miss) |
| (나) 그중 세 탐지기가 모두 놓친 것만 | H / (N − S_miss) |

- (나)는 걸린 쪽의 script_only(S_hit)를 분모에서 빼지 않는다. 그래서 S_hit > 0이면 항상 (가)보다 높다. 예: N=6,658, H=3,653일 때 S_hit=100, S_miss=500이면 (가) 0.586, (나) 0.593.
  - 걸린 샘플도 본문에 공격이 없을 수 있다. 정적 규칙이 무해한 줄에 걸리는 경우다.
- (나)는 판정 대상이 탐지기 결과에 따라 정해진다. 공지 "미탐만으로 제외하지 않는다"와 부딪힌다. 탐지기를 바꾸면 대상도 바뀐다.
- (가)는 대상이 패키지 내용만으로 정해진다. 그래서 세 탐지기에 같은 대상, 같은 판정을 쓸 수 있다.

## 2. 판정 방식: ③ 층화 무작위 표본 + 추정

### 2.1 대상 크기 (dev 악성 6,658개, 관찰)

| | 수 | 정적 v1 걸림 |
|---|---:|---:|
| 코드 파일 없음(판정 없이 분모에 남음) | 2,168 | 1,126 |
| 코드 파일 있음(판정 대상 C) | 4,490 | 2,527 |
| └ SRC010 | 2,596 | 2,012 |
| └ SRC001 | 1,721 | 503 |
| └ 기타(SRC013 69, SRC006 64, SRC002 21, SRC004 18, SRC008 1) | 173 | 12 |

①(전수 사람 판정)과 ②(에이전트 1차 + 담당자 확인)를 쓰지 않는 이유:
- 둘 다 4,490건을 판정해야 한다.
- ②는 에이전트가 악성 코드를 대량으로 읽어야 한다. 실제로 한 번 안전 필터에 막혔고, Windows Defender도 대화 기록을 잡는다. 담당자 확인도 결국 수천 건이다.

### 2.2 표본 추출

- **층**: 출처별로 나눈다. 코드 있는 악성이 100개 이상인 출처는 따로 한 층으로 두고, 나머지 출처는 "기타" 한 층으로 합친다. 이 규칙은 출처 이름이나 수를 미리 알 필요가 없어서 test에도 그대로 쓸 수 있다.
- **배분**: 층 크기에 비례해 나누고 남는 자리는 소수점 아래가 큰 층부터 채운다. 층마다 최소 2개를 뽑는다. `random_state=0`.
- dev에서 n=30이면 SRC010 16, SRC001 12, 기타 2가 된다. n=100이면 58, 38, 4다. 기타 층은 C 안에서 차지하는 비중이 3.9%라 추정값에 미치는 영향이 작다.
- dev 시트: `docs/experiments/script_only_dev_sheet.csv`(30개, 다시 뽑아도 같은 파일).
- **이미 판정한 90개**는 추정에 쓰지 않는다. 미탐에서만 뽑았기 때문이다. dev 표본 30개와 겹치는 것은 2개인데, 이 2개도 같은 판정 시트로 다시 판정한다. E4 text_attack은 코드를 보지 않은 발췌 판정이라 §8.2 절차와 다르다.

### 2.3 판정

- **판정 시트(에이전트가 만듦, 원문 없음)**: 표본마다 benchmark_id, 코드 파일 목록과 수, 자동 코드 근거(`파일:줄:동작`), SKILL.md가 부르는 파일 이름을 적는다. 탐지기 결과 열은 넣지 않는다.
- **판정자**: 원문을 Claude 채팅 밖에서 직접 읽고 E6 §8.2 표대로 text_attack, script_only, unclear 중 하나로 정한다. script_only에는 `code_evidence`에 `파일:줄 동작`, text_attack에는 `skill_evidence`에 본문 줄 번호를 적는다.
- **원문 보기**: `cd data && python -I script_only_view.py <ID> [파일 이름 일부]`. 압축을 풀지 않고 SKILL.md와 코드 파일을 줄 번호와 함께 담당자 터미널에만 출력한다. 아무것도 실행하지 않는다.
- **판정 시트 열**: `benchmark_id, stratum, C_h, n_h, n_code, code_files, named_in_skill, auto_evidence`(자동) + `verdict, code_evidence, skill_evidence, judge, note`(판정자가 채움).

### 2.4 추정식

2026-11-10에 계산 방법을 유한모집단 베이즈로 바꿨다(PR #9 리뷰 2번, 아래 "바꾼 이유"). 표본 설계(§2.2)와 판정(§2.3)은 그대로다.

후보(코드 있는 악성) 전원의 층 h와 탐지기 걸림 g는 알고 있으므로, 층 h × 걸림 g 칸마다 다음을 둔다.
N_hg = 칸의 후보 수(정확히 앎), n_hg = 칸에 든 표본 수, s_hg = 그중 script_only 수.

- 칸마다 조사하지 않은 N_hg − n_hg개 중 script_only 수를 Beta-Binomial(N_hg − n_hg, s_hg + a, n_hg − s_hg + a)에서 뽑고 s_hg를 더한다.
- K₁ = 걸림 칸의 script_only 합, K = 모든 칸의 합.
- **제외 재현율 R = (H − K₁) / (N − K)**. H와 N은 전체 악성에서 정확히 센 값이고 추정값이 아니다.
- **대표값은 R 분포의 중앙값, 범위는 "95% 베이즈 구간"**(10,000회, seed 0의 2.5·97.5 백분위)으로 적는다. 전체 재현율·오탐률의 "95% 신뢰구간"과 이름을 구분한다. script-only 비율 K/C도 같은 방법으로 적고, unclear는 건수를 적는다.
- **사전분포는 a = 0.5(Jeffreys)를 주 결과로 고정**한다. 같은 판정표로 a = 1(균등)도 늘 함께 계산해 차이를 확인한다. 성적이 좋게 나오는 쪽을 나중에 고르는 용도가 아니며, 스크립트도 a를 실행 옵션으로 받지 않고 두 값을 함께 출력한다.
- 분모 N − K가 0이 되는 경우는 "정의 안 됨"으로 적는다.

가정:
- 층 안 표본은 비복원 단순 무작위이므로, 걸림 칸 안의 표본도 그 칸의 단순 무작위 표본으로 본다. 그래서 칸 크기를 알기 위해 추정 스크립트가 후보 목록(`script_only.py` 출력, 표본을 뽑은 것과 같은 파일)을 입력으로 받는다.
- 칸마다 따로 사전분포를 둔다. 표본이 하나도 들지 않은 칸은 사전분포만으로 뽑으므로 구간이 넓어진다.
- 칸을 탐지기마다의 걸림으로 나누므로, 같은 판정표라도 script-only 비율 K/C가 탐지기마다 조금 다르게 나올 수 있다. 예: dev 가상 판정(§2.5)에서 정적 score > 0은 중앙값 0.350, score ≥ 0.6667은 0.351.
- script_only가 아닌 판정(text_attack, unclear, label_noise)은 제외하지 않고 분모에 남긴다(§3).

이렇게 하면 다음이 계산 구조상 성립한다. 가상 사례는 `tests/test_script_only_est.py`에 테스트로 남겼다.
- 표본에서 script_only가 0개여도 조사하지 않은 후보가 있으면 구간이 한 점으로 고정되지 않는다.
- K₁이 걸린 후보 수를 넘지 않으므로 값을 자르지 않아도 R이 0~1 안에 있다.
- 전수조사한 칸은 표본추출 불확실성이 0이다.
- 분모가 0이면 멈추지 않고 "정의 안 됨"을 낸다.

바꾼 이유: 11-07~11-09의 층화 bootstrap(Ŝ = Σ C_h·s_h/n_h, Ŝ_hit = Σ C_h·s_h,hit/n_h로 (H − Ŝ_hit)/(N − Ŝ))은 위 네 경우를 처리하지 못했다(관측 0이면 구간 0.600~0.600, 작은 자료에서 −1.600~0.480, 전수조사 층에도 불확실성, 분모 0이면 중단). dev 칸 크기로 만든 가상 모집단에서 95% 구간이 참값을 포함한 비율은 아래와 같다(조건마다 400번, `data/script_only_ci_trial.py`). 실제 판정·test는 쓰지 않았다.

| 가상 script-only 비율(걸림 / 안 걸림) | n=100 새 방법 / 예전 bootstrap | n=30 새 방법 / 예전 bootstrap |
|---|---|---|
| 10% / 35% | 94.0% / 95.2% | 95.8% / 92.5% |
| 1% / 2% | 99.0% / 61.5% | 100% / 24.8% |
| 40% / 70% | 94.0% / 93.5% | 94.2% / 93.0% |

- 탐지기 결과는 판정이 끝난 뒤 이 계산에만 쓴다. 세 탐지기는 같은 표본, 같은 판정 csv, 같은 식을 쓰고 걸림 열만 각자의 동결 기준으로 만든다.
- **s1_eval.py는 고치지 않는다.** 지금 `--script-only`는 csv에 있는 script_only ID만 분모에서 뺀다. 표본 시트를 넣으면 표본 안의 script_only 몇 개만 빠지고 나머지 대상은 판정 없이 분모에 남아 틀린 값이 나온다. 그래서 추정은 별도 스크립트로 한다(§6).

### 2.5 표본 크기: test 100, dev 30

script-only 비율과 그 분포를 모르기 때문에 가정을 두고 모의 계산했다. 정적 v1의 실제 걸림을 쓰고, C 안에서 script_only를 무작위로 정한 뒤 단순 무작위 표본으로 2,000회 추정했다. 층화하면 이보다 같거나 조금 좁다.

| 가정: C 안 script-only 비율 | 미탐 쪽에 몰림(odds) | 참값 | n=100 95% 범위 | n=200 95% 범위 |
|---|---|---:|---|---|
| 10% | 같음 | 0.549 | 0.527~0.572 (±2.3%p) | 0.533~0.566 (±1.7%p) |
| 10% | 4배 | 0.570 | 0.548~0.597 (±2.5%p) | 0.555~0.588 (±1.7%p) |
| 20% | 같음 | 0.545 | 0.513~0.578 (±3.3%p) | 0.522~0.568 (±2.4%p) |
| 20% | 4배 | 0.592 | 0.556~0.633 (±3.9%p) | 0.568~0.618 (±2.5%p) |
| 40% | 같음 | 0.544 | 0.488~0.598 (±5.5%p) | 0.507~0.580 (±3.7%p) |
| 40% | 4배 | 0.619 | 0.558~0.678 (±6.0%p) | 0.577~0.662 (±4.2%p) |

- script-only 비율 자체는 n=100이면 ±10%p까지 흔들린다. 하지만 제외 재현율의 구간은 그보다 좁다. 코드 없는 2,168개는 판정 없이 정확히 알고, 걸린 쪽 script-only 수와 전체 script-only 수가 분자와 분모에서 같은 방향으로 움직이기 때문이다. (이 표는 11-07에 예전 점추정식으로 낸 표본 크기 모의 계산이다. 보고 방법은 §2.4.)
- 판정은 사람이 한 건씩 원문을 읽어야 한다. 보고에 쓰는 값은 test 제외 재현율이라 test에 100개를 쓴다. 200은 두 사람이 나눠 판정할 때만 권한다.
- dev 30개는 절차 점검용이다. 판정 시트만으로 판정이 되는지, 두 사람의 판정이 맞는지를 본다. 판정은 동결 뒤 test 판정 전에 하고, 기준 문구는 동결 때 것(E6 §8.2)으로 고정해 바꾸지 않는다. 애매한 사례는 `note`에 적고 unclear로 둔다. 구간은 n=100보다 약 1.8배(√(100/30)) 넓어서 dev 제외 재현율은 참고값으로만 보고한다. 예: 가상의 판정(30개 중 script_only 10개)을 넣어 보면 95% 구간이 0.434~0.605였다(11-07 bootstrap 기준, 스크립트 점검용 값, 실제 판정 아님). 11-10 방법으로 시트 앞 10행을 script_only, 나머지를 text_attack으로 둔 가상 판정은 중앙값 0.655, 95% 베이즈 구간 0.614~0.695(a=1: 0.652, 0.603~0.694)였다. 앞 10행이 모두 SRC001 층이라 치우친 가상 판정이며, 역시 점검용 값이다.

## 3. 판정자와 일치도

- 왕민이 dev 30개, test 100개를 모두 판정한다.
- 표본 안에서 seed 0으로 고른 dev 10개, test 20개는 세훈 님이 따로 판정한다(11-09 확정). 보조 판정자도 판정 시트만 보고, 탐지기 결과는 보지 않는다.
- 보고할 것: 일치 건수(x/10, x/20), 판정 쌍별 표(3×3). 이 정도 수로는 κ가 불안정해서 참고로만 적는다.
- 불일치는 두 사람이 근거를 놓고 다시 본다. 그래도 합의가 안 되면 unclear로 둔다. 근거가 부족한 사례(unclear)는 제외하지 않고 분모에 남기며, 이로 인해 남는 분류 불확실성은 한계로 보고한다. unclear가 걸린 샘플인지 놓친 샘플인지에 따라 제외 재현율은 높게도 낮게도 나올 수 있어, 항상 보수적인 값이 되지는 않는다.

## 5. test 적용 절차

1. 세훈 님이 test 악성에 `data/script_only.py`를 돌려 코드 파일 유무와 자동 근거를 만든다.
2. 같은 표본 추출 스크립트(같은 층 규칙, n=100, seed 0)로 test 표본을 뽑는다: `python -I script_only_sample.py <test script_evidence csv> 100 <test 시트 csv>`.
3. 판정 시트를 만들고, 판정자가 탐지기 결과를 보지 않고 판정한다. 판정자는 왕민(동결 뒤)이고, 교차 판정 20개는 세훈 님이 한다. test를 본 뒤에는 탐지기, 기준, 식 어느 것도 바꾸지 않는다.
4. 판정 csv가 다 채워진 뒤에 세 탐지기의 걸림 열을 붙여 같은 식으로 추정한다. 후보 목록은 2번에서 표본을 뽑은 것과 같은 `script_evidence csv`를 쓴다.
5. 보고: 전체 재현율(기본 성적)과 script-only 제외 재현율(표본으로 추정한 보조 성적: 중앙값과 95% 베이즈 구간, a=0.5 주·a=1 함께), script-only 비율 K/C, unclear 비율, 표본 크기, 일치도.

## 6. 스크립트 (11-07 작성)

- `data/script_only_sample.py`: 입력은 `script_only.py` 출력(`n_code`, `source_id`). §2.2 규칙대로 표본을 뽑아 판정 시트(원문·탐지기 결과 없음)를 만든다. 같은 입력·n·seed면 같은 파일이 나온다.
- `data/script_only_est.py`: 판정이 모두 채워진 시트, 후보 목록(`script_only.py` 출력), 정답 csv, 탐지기 결과 jsonl, 걸림 문턱을 받아 칸별 후보·표본·script_only 수, script-only 비율과 제외 재현율(중앙값, 95% 베이즈 구간, a=0.5·a=1), unclear 수를 낸다. 세 탐지기가 함께 쓴다. 판정이 빈 행, 중복 id, 후보가 아닌 id가 있거나 시트의 층·C_h가 후보 목록과 다르면 멈춘다. (11-10 개정, 11-07판은 bootstrap)
  - 사용: `python -I script_only_est.py <시트 csv> <script_evidence csv> <정답 csv> <결과 jsonl> --threshold T [--ge]`
  - 정적: `--threshold 0`(score > 0). AI 판정기: `--threshold <문턱> --ge`(score ≥ 문턱).
  - 확인: `python -m pytest tests/test_script_only_est.py`. 리뷰 가상 사례 4개(관측 0, 작은 자료, 전수조사, 분모 0)를 a=0.5·a=1 모두에서, 전수조사 가상 시트로 실행 전체(참값 0.500 한 점)와 시트·후보 목록 불일치 4종을 확인한다.
- `data/script_only_ci_trial.py`: §2.4 "바꾼 이유"의 가상 사례·coverage 비교를 다시 내는 기록용. test 순서에는 쓰지 않는다.
- `data/script_only_view.py`: 판정자 터미널 전용 원문 보기(§2.3).

## 7. 미확정일 때

기한까지 정하지 못하면 script-only 기준은 "미확정"으로 둔다. 그러면 test는 전체 기준만 보고한다(`docs/stage1_freeze.md` §1). 그 경우 dev 판정 90개(§8.3)는 사례 기록으로만 남기고, 재현율 계산에는 쓰지 않는다.
