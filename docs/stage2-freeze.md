## 4. 문턱을 이렇게 정한 이유

- **관찰:** LLM 점수는 분류별로 뭉친다(SAFE 약 0.02, SUSPICIOUS 약 0.57, MALICIOUS 약 0.98). 0.6~0.95의 어떤 문턱도 2/3과 거의 같으므로 실제 선택지는 "SUSPICIOUS를 걸림으로 치느냐"다. SUSPICIOUS는 악성 1,549, 정상 135다.
- **LLM 2/3:** 오탐 11.66%는 정상 스킬 9개 중 1개를 막는 수준이라 주 기준으로 쓰기 어렵다. 2/3은 악성 1,549개를 놓치는 비용이 있어서 0.5 숫자를 항상 함께 보고한다.
- **Jev 0.5:** 정상 중 최고 점수는 0.46이다. 0.3이면 악성이 3,522개로 늘고 오탐은 7개다. 그러나 정상의 1,643/1,690개가 SRC010 한 출처라 이 여유가 다른 출처에서도 유지된다는 근거가 없다. 그래서 낮추지 않는다.
- 이 문턱은 dev 결과를 본 뒤 test를 보기 전에 정했고, test 결과를 보고 바꾸지 않는다.
- 네 칸 기준이 2026-10-12 합의(판정기 ≥ 0.5)에서 달라진다. LLM은 두 기준을 모두 낸다.

- 한계: dev 전체를 v0로 돌리지 않아 1,173개 전체의 효과는 재지 않았다. 긴 문서 표본은 16개뿐이라 v1이 낫다는 근거로는 약하다. v1을 고른 근거는 아래 합성 실험과 "잘린 구간은 입력에 아예 없다"는 구조적 이유다.

### 인위적으로 공격을 심은 실험 (합성, 사람이 고른 악성 문단)

dev 정상 중 15,000~30,000자 5개(dev100·새로운 dev100 제외, seed 42)의 잘리는 구간 가운데 문단 경계에 악성 문단 3종을 심었다. Jev, 0.5 기준, 걸린 수/5.

| 입력 | 자르기 v0 | 자르기 없음 | 문단별 | 1,500자 묶음 |
|---|---|---|---|---|
| 원본(공격 없음) | 0 | 0 | 2 | 0 |
| ① 명시적 공격 | 0 | 5 | 5 | 5 |
| ② 지시와 위장을 다른 문단으로 | 0 | 0 | 2 | 0 |
| ③ 지시와 위장이 한 문단 | 0 | 0 | 2 | 0 |

②·③의 문단별 2개는 악성 조각이 아니라 원본에서도 오탐 난 정상 조각 때문이다(악성 조각 점수 0.05~0.23).

### 분할 입력

- 조건: Jev만 시험했고 LLM은 돌리지 않았다. 표본은 dev100 100개와 위 합성 20개다. 단위는 빈 줄 기준 문단(P), 또는 문단을 1,500자까지 묶음(K)이고 겹침은 없다. 조각 점수의 최댓값을 문서 점수로 쓴다. 호출 8,793, 실패 0, 전체 $0.31.
- 코드: `skillsplit/stage2/experiments/split_input.py`, `split_input_summary.py`. 요약: `docs/experiments/stage2_split_input/`.

| dev100, Jev 1회, 0.5 | 악성 | 오탐 | 호출 | 입력 글자 |
|---|---|---|---|---|
| 자르기 v0 (A) | 27/50 | 0/50 | 100 | 531,887 |
| 원문 그대로 (B) | 27/50 | 0/50 | 100 | 619,257 |
| 문단별 (P) | 30/50 | 1/50 | 4,661 | 609,676 |
| 1,500자 묶음 (K) | 28/50 | 0/50 | 495 | 618,008 |

- 조건별 비용은 따로 재지 않았다. Jev 비용은 입력 토큰에 비례하므로 글자 수가 비슷한 B, P, K의 비용도 비슷할 것으로 추정한다. 호출 수는 P가 47배다.
- 통째와 조각을 합친 규칙은 평균 27/0, 조각 ≥ 0.9 27/0, 조각 ≥ 0.7 28/0이다(결과를 보고 고른 문턱이라 낙관적이다).
- **결정: 동결본에 넣지 않고 후속 실험으로 둔다.** dev100의 이득은 3/50이고, 긴 정상 글 5개 중 2개를 오탐하며, 오탐을 막으면 이득이 거의 사라진다.

### 모델 한도를 넘는 문서

- 관찰: dev의 입력 토큰 최대는 LLM 33,539, Jev 32,010(21MB 이상치)이고, 다음으로 큰 Jev 입력은 18,387이다. dev에서 한도 때문에 실패한 문서는 없다. Jev 한도는 32k 토큰으로 알려져 있어 이상치가 한도에 붙어 있다.
- 결정: 코드를 바꾸지 않는다. 자르기 v1 뒤에도 한도를 넘으면 Jev는 4xx로 바로 실패해 점수 2/3이 되고 details에 `failed`로 남는다. 실패 건수로 따로 보고하며 다시 돌리지 않는다. LLM은 60,000자 입력이 입력 한도보다 훨씬 작아 해당이 없다.

## 7. test 예상 (실행 전 기록, 2026-11-07)

test 폴더를 만들기 전에 적었다. 근거는 공개 논문, 팀 문서, dev 결과뿐이다.

| 판정기 | 재현율 예상 (악성 839개) | 오탐률 예상 (정상 545개) |
|---|---|---|
| LLM 2/3 | 25%, 약 210개 (범위 17~32%, 143~268개) | 1%, 약 5개 (범위 0.4~3%, 2~16개) |
| LLM 0.5 | 50%, 약 420개 (범위 35~62%, 294~520개) | 6%, 약 33개 (범위 2~12%, 11~65개) |
| Jev 0.5 | 11%, 약 92개 (범위 6~15%, 50~126개) | 0% (범위 0~1%, 0~5개) |

점 예상과 범위는 아래 근거 사이에서 고른 판단이고 계산식으로 나온 값이 아니다.

### 근거

1. **같은 test, 같은 모델의 공개 성적.** SkillScreen(arXiv 2610.17727 v2) Table 1, 문턱 0.5, SKILL.md의 앞 8,192토큰 입력. Source-Disjoint test(악성 839, 정상 545)에서 Claude Haiku 4.5는 재현율 28.8%·오탐률 0.6%, TypeSafe Jev 1.13은 11.3%·0.0%다. 같은 논문의 Malicious-Structural-Disjoint test에서는 Haiku 65.9%·2.9%, Jev 33.8%·0.2%다(2026-11-07 원문 확인).
2. **우리 2/3 기준은 그 논문의 Haiku 설정과 엄격함이 비슷하다.** 우리 dev 전체는 재현율 66.72%·오탐률 3.67%이고, 논문의 Malicious-Structural-Disjoint test는 65.9%·2.9%다. 두 시험지는 구성이 다르다(논문 쪽에는 test 출처가 섞여 있다. 악성 7,497개 중 839개가 고르게 섞였다고 가정하면 나머지 출처에서 약 70.6%).
3. **dev의 낯선 출처 성적.** SRC001·SRC010을 뺀 악성 457개에서 LLM 2/3 76/457(16.6%), LLM 0.5 215/457(47.0%), Jev 0.5 26/457(5.7%). 출처별로는 LLM 2/3 0~23%, LLM 0.5 10~64%, Jev 0~9%다(악성 30개 이상인 출처).
4. **0.5 기준의 증가분.** dev에서 2/3을 0.5로 낮추면 재현율이 출처별로 10~41%p 늘었다(전체 +23.3%p, 낯선 출처 +30.4%p). LLM 2/3 예상 25%에 이 증가분을 더했다.
5. **오탐.** LLM 2/3은 근거 1의 0.6%에서 출발해, 우리 dev 오탐률이 논문보다 조금 높은 점(3.67% 대 2.9%)을 반영했다. LLM 0.5는 dev에서 0.5 오탐이 2/3의 3.2배(197 대 62)였다는 점과, test 정상 455개(ATR)가 일부러 헷갈리게 고른 정상이라는 점으로 잡았다. 이 칸의 근거가 가장 약하다. Jev는 dev 오탐 0/1,690(정상 최고 점수 0.46)과 논문의 0.0%를 썼다.

LLM 2/3을 논문의 28.8%보다 낮은 25%로 잡은 이유: 프롬프트 v2의 개선이 모두 SRC010에서 나와 다른 출처로 옮겨 간다는 근거가 없고(§6), dev의 낯선 출처 성적이 16.6%다.

### 예상이 틀릴 수 있는 곳

- 프롬프트와 걸림 기준이 논문과 다르다. 논문은 확률 0.5 이상, 우리는 세 등급 중 MALICIOUS만이다. 입력 범위 차이(8,192토큰 대 60,000자)는 dev에서 99/8,348개에만 해당해 영향이 작다.
- test 악성 839개 중 728개가 SkillHarm 한 출처다(SkillScreen Table 3). 이 출처의 성격을 모른다. 지시가 글에 드러나는 유형이면 예상보다 높고, 공격이 동봉 스크립트에만 있으면 낮다.
- 논문은 Jev 1.13이고 우리 기록에는 Jev 버전이 남지 않는다. 질문도 다르다(논문은 가설 한 문장, 우리는 `jev_questions_v0.json`).
- 표본 839개의 통계 오차는 약 ±3%p다. 범위가 넓은 이유는 표본 크기가 아니라 위 차이들이다.
