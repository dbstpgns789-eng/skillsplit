# AI 판정기 test 결과 (2026-11-11, freeze-v1, LLM·Jev 각 1회)

test는 held-out 1,384개(악성 839, 정상 545)이고 공통 동결 뒤 처음 열었다. 걸림 기준은 동결 때 정한 LLM ≥ 2/3(0.5 병기), Jev ≥ 0.5, 정적 > 0이며 결과를 보고 바꾸지 않았다. 전체 표(문턱 후보별, 실패 장부, 출처별, 네 칸, 결합, 비용)는 [stage2_test_report.md](experiments/stage2_test_report.md)에 `report_thresholds` 출력 그대로 있다. 실행 전 예상은 [stage2-freeze.md](stage2-freeze.md) §7.

## 2. 중단·오류·재개

1. 00:00:01에 시작한 첫 실행(r0)은 Windows Defender가 LLM 요약 파일을 `Trojan:PowerShell/Obfus.YYG!MTB`로 탐지(00:02:10, 00:02:17)해 00:03경 격리했다. 판정기는 파일을 덧붙이기만 하므로 0바이트로 비워진 뒤 다시 쌓였고, details 96건 중 요약 44건만 남았다. 00:05에 중단하고 r0 전체를 폐기했다(잘린 파일은 보존). 원인은 요약 파일의 근거 인용에 악성 스킬의 명령 줄이 그대로 들어가서다. 텍스트 파일이며 실행하지 않는다.
2. 00:06:11에 처음부터 다시 실행(r1). 실행 중 결과 파일을 열지 않았고, LLM·Jev 모두 1회 시도로 끝났다. 재개·API 재호출 없음. r0가 쓴 호출 96건(약 $0.3)은 r1과 무관하다.
3. r1 완료 직후(01:13:08, 01:13:21) 같은 파일이 다시 격리됐다. details는 영향 없음. Defender 제외 폴더(`runs`, `data`, 공유 폴더)를 등록한 뒤 격리본을 복원했고, 복원본은 01:12:37 완성본(231,031바이트, 1,384줄)이다. 복원 뒤 네 파일 모두 1,384줄, ID 누락·중복 0을 확인했다.

교훈: 결과 파일을 받는 쪽도 백신 제외를 먼저 걸고 해시를 확인해야 한다. 11-04 dev 때도 `dev_skills`의 SKILL.md 여러 개가 Defender에 탐지된 기록이 있다.

## 6. 하지 않은 것, 다음

- script-only 제외 재현율: 왕민·세훈의 사람 판정이 끝난 뒤 같은 판정표로 `data/script_only_est.py`에 넣는다(LLM `--threshold 0.6667 --ge`, Jev `--threshold 0.5 --ge`). 판정이 끝나기 전에는 표본 ID별 탐지 결과를 판정자에게 보내지 않는다.
- test 대표 사례 원문 대조는 아직 안 했다. 세훈의 검산 뒤, 학술제 보고서용으로 오탐 4개와 "둘 다 놓침" 유형 몇 개를 고른다.
- 결과를 보고 기준·프롬프트·질문 파일을 바꾸지 않는다. 개선은 별도 실험으로 구분한다.
- 후속 실험 후보: 근거 인용에서 보이지 않는 문자를 지우거나 max_tokens를 늘려 숨긴 문자 스킬의 출력 끊김을 막기(위 ASB04_004158).
