# E4. E3의 "정규식으로 못 잡는 약 540개"는 교묘한 공격인가, 라벨 문제인가

실행일 2026-10-12. 담당 정적 탐지기(왕민). dev만 사용, test는 보지 않았다. [E3](E3_src001_missed.md) §6의 후속이고, PR #3 리뷰의 부탁에 대한 답이다.

악성 원문은 이 문서에 옮기지 않는다. 판정에는 URL·코드·명령을 가리고 200자로 자른 발췌만 썼다(§1-3).

## 0. 한 줄 결론

- 대상은 정확히 **539개**다(E3의 "약 540개"). seed 0으로 50개를 뽑아 판정했다.
- **라벨 잡음은 1/50(2%)**이다. 95% 신뢰구간은 0.4~10.5%이고, 539개로 환산하면 많아야 약 57개다. "대부분 라벨 문제"라는 설명은 성립하지 않는다.
- **37/50(74%)은 SKILL.md 글 안에 악성 지시가 그대로 있다.** 지시 무력화, 시스템 프롬프트 유출, 페르소나 바꾸기, 답 편향시키기, 작업 환경 정찰, 스크립트 실행 유도 등이다. 교묘하게 숨긴 것이 아니라 **기존 도구의 키워드·코드 규칙이 보지 않는 종류**일 뿐이다. 그래서 E3 §0의 "평범한 문장에 의도만 악성이라 정규식의 한계 밖"이라는 표현은 고쳐야 한다(§4).
- **10/50(20%)은 공격이 동봉 스크립트에만 있다.** SKILL.md는 스크립트를 평범한 도구처럼 이름으로 부를 뿐이다. SKILL.md만 입력으로 쓰는 공식 평가에서는 글에 근거가 없다. 라벨은 패키지 기준으로 맞지만 **입력 범위 밖**이다.
- 판단 보류는 2/50이다.

## 1. 방법

### 1-1. 대상

E3 `src001_signals.py` 기준으로, 두 도구가 놓친 SRC001 1,498개에서 아래를 모두 뺀 것이 539개다. 목록은 `runs_dev/e4_residual.csv`에 있다.

- marker
- 지시 신호(init_directive·prompt_leak·operates_under)
- op_heading

메타데이터상 539개는 모두 다음과 같다.

| 항목 | 값 |
|---|---|
| `evidence_type` | `human+runtime` |
| `release_status` | `FULL_TEXT` |
| 가림 처리 | 12개 |
| 카테고리 없음 | 332개 |

### 1-2. 같은 바탕 글과 비교 (`e4_diff.py`)

dev 8,348개를 문단 단위로 해시해, 539개 각각과 공유 문단이 가장 많은 다른 샘플을 찾았다.

- 공유 문단이 3개 이상인 기준 샘플이 있는 것은 **228개**다. 기준 샘플은 227개가 악성, 1개가 정상이다.
- 기준 샘플과 1~2문단만 다른 것이 96개다. 이 경우 주입 부분이 그 문단으로 좁혀진다.
- 539개의 `structural_family_id`(509종) 중 정상을 포함한 묶음은 **0개**다. 같은 원본의 깨끗한 정상본은 데이터에 없다.

### 1-3. 판정 (`e4_excerpt.py`, [E4_judgments.csv](E4_judgments.csv))

샘플마다 아래를 봤다.

- 소제목 목록
- 에이전트·지시 관련 단어가 많은 산문 문장 5개
- 기준 샘플이 있으면, 기준 샘플에 없는 문단

이것으로 판단이 안 된 15개는 추가로 확인했다.

- 코드 블록 키워드, 숨은 문자(zero-width·bidi), 라틴+키릴 혼용 단어, HTML 주석
- MaliciousSkillBench `packages/SRC001_packages.tar.gz`(sha256 `878498b4…`, `SHA256SUMS.txt`와 일치)의 동봉 파일. 해당 id만 메모리에서 읽고, 키워드와 URL 수만 셌다. 디스크에 풀지 않았다.

판정 기준은 아래와 같다.

| 판정 | 기준 |
|---|---|
| text_attack | SKILL.md 글에 사용자 몰래 에이전트의 목표·출력·권한을 바꾸거나, 정보를 빼내거나, 출처를 알 수 없는 코드 실행을 유도하는 지시가 있음 |
| script_only | 글에는 그런 지시가 없고, SKILL.md가 이름으로 부르는 동봉 스크립트에 네트워크 전송·실행·인코딩 등이 있음 |
| label_noise | 글과 동봉 파일 어디에서도 악성 동작이나 지시를 찾지 못함 |
| unclear | 위 셋 중 하나로 정하기 어려움 |

## 3. 해석

- **"정규식 한계 = LLM 몫"이라는 E3의 구분은 반만 맞다.** 74%는 글에 의도가 드러난 지시문이다. 다만 유형이 여러 갈래다(override·prompt_leak·persona·bias·recon…). E3의 좁은 정규식(init_directive 등)이나 기존 도구의 위험 키워드에 걸리지 않았을 뿐이다. 일부(prompt_leak, override, recon)는 "에이전트에게 지시문·환경 정보를 출력하라고 함"처럼 행위 규칙으로 쓸 수 있다. bias·persona는 정상 스킬의 "이 관점에서 답하라"와 구분이 어려워 LLM 판정 쪽이 맞다.
- **script_only(약 20%)는 SKILL.md만 보는 탐지기의 구조적 한계다.** 정적이든 LLM이든 글만으로는 근거가 없다. 평가 보고 때 "입력 범위 밖" 샘플로 따로 표시하는 것을 제안한다(팀 결정 필요).
- **E3 §2의 "동봉 스크립트 때문은 아니다"와 충돌하지 않는다.** E3는 SRC001 전체에서 파일 수별 놓친 비율이 같다는 집계였다. E4는 신호가 하나도 없는 잔여 539개 안에서 20%가 스크립트형이라는 것이다. 잔여 집합에는 스크립트형이 상대적으로 몰려 있다.
- **라벨 잡음 상한은 약 10%다.** 표본이 50개라 "없다"고는 못 한다. 확인된 1건은 "공격 문단이 빠진 형제 변형"이라는 구체적인 형태라서, 같은 형태를 전체 539개에서 자동으로 찾을 수 있다(§5).

## 4. E3 수정 사항

E3 §0과 §6의 "남은 약 540개는 평범한 문장에 의도만 악성이라 정규식의 한계 밖"을 이렇게 바로잡는다.

> 539개 중 약 74%는 글에 악성 지시가 드러나 있으나 기존 키워드·E3 정규식이 다루지 않는 유형이고, 약 20%는 공격이 동봉 스크립트에만 있어 SKILL.md 입력 범위 밖이며, 라벨 잡음은 2%(상한 약 10%)다.

## 5. 주의

- 판정자는 1명(왕민)이다. 2차 판정이나 일치도는 없다. 원문 대신 가린 발췌만 봤으므로, 발췌에 안 걸린 곳의 공격을 놓쳤을 수 있다. 그 경우 label_noise가 과대 추정된다.
- script_only는 스크립트 코드를 읽지 않고 키워드(requests·subprocess·base64 등)와 URL 수로만 판정했다. 동작을 확인하지 않았다.
- 다음에 할 만한 것:
  - "형제 변형보다 문단이 적고, 빠진 문단이 형제에서 잡힌 부분"인 샘플을 228개 전체에서 자동으로 세기(라벨 잡음 후보 전수)
  - prompt_leak·override·recon을 행위 규칙으로 일반화해 2주차 규칙 초안에 넣고, 정상 오탐 확인하기
