# E2. 두 도구가 모두 놓친 악성 분석 (1차)

실행일 2026-10-08. 담당 정적 탐지기(왕민). dev만 사용, test는 보지 않았다. 기준선은 [E1](E1_baselines_dev.md)의 Cisco 기본 설정 + SkillGate 규칙만.

악성 원문은 이 문서에 옮기지 않는다(재배포 금지, Defender 탐지). 사례는 benchmark_id와 요약으로만 적는다.

## 0. 한 줄 결론

- 놓친 악성 3,052개의 92%가 **SRC001(1,498)과 SRC010(1,295)** 두 출처다.
- injected는 거의 같은 주입 틀이다: 정상 스킬 앞부분에 "필수 선행 단계"라며 로컬 스크립트 실행을 지시하고, 사용자에게 알리지 말라는 문구를 붙인다.
- 이 틀을 행위로 일반화한 신호를 기존 Cisco와 OR로 묶으면 dev에서 **재현율 0.310 → 0.513, 오탐률 0.008 → 0.023**이 된다. 그러나 효과의 대부분이 **SRC010 한 출처의 주입 틀**에서 나오므로, dev에 없는 출처로 구성된 test에서도 통한다고 기대하면 안 된다.
- SRC001의 놓친 악성은 공통 틀이 없고 다양하다. 카테고리 정보가 없는 것이 925개다. 이번 신호로는 3.5%만 잡힌다.

## 4. 해석과 주의

- **dev 수치 상승은 대부분 SRC010 주입 틀 덕분이다.** test는 dev에 없는 출처로 구성되므로(공식 출처 분리), 한 출처의 틀에서 나온 효과는 일반화를 보장하지 않는다. 이들은 "벤치마크 생성기를 맞힌 규칙"일 수 있다는 전제로 다룬다.
- 그래도 "스킬 문서가 에이전트에게 출처를 알 수 없는 로컬 코드 실행을 강요하고 사용자에게 숨기라고 함"은 실제 공격(R1의 지시 조작·실행 계열)과도 맞는 행위다. 밑줄 파일명 규칙과 달리 남겨 둘 근거가 있다.
- homoglyph와 lure는 실제 배포 출처(SRC001)에서 나오고 정상 오탐이 거의 없다. 다만 잡는 수가 적다.
- desc_bypass는 정상 13개(보안 도구 스킬로 보임)에서 걸려 단독으로 쓸 수 없다. conceal(정상 9)도 다른 신호와 묶을 때만 쓴다.
- SRC001의 놓친 악성(1,498)은 이번 신호로 거의 안 잡힌다. 다음 분석의 중심이다.
